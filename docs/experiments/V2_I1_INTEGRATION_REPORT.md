# V2-I1：第一次系统级集成尝试报告

日期：2026-07-25
协议：`experiments/V2_I1_INTEGRATION_PROTOCOL.json`（实现前冻结）
状态：**开发集未通过，一次性留出未消费**

## 目的

这不是能力开发，是"系统级环"能否被验证的第一次真实尝试：把 M2 的
`OnlineEntityGraph`（实体关联+在线控制辨识）和 M4 去特权化的
`UnprivilegedOccupancyMemory`（shadow-casting+对象永久性）组合进
**同一个 agent、同一个世界、同一条按时间顺序的经验流**，用同一次
`update(sensed_occupancy, action)` 调用同时驱动两者。

**自我发现完全失效（F1=0.000）**，永久性接近但未过（0.538 vs 0.55）。
这是诚实的失败，不是没跑起来。

## 根因诊断（三处结构性摩擦）

**1. 运动尺度不匹配。** `OnlineEntityGraph` 的关联代价函数里
`motion_cost = (distance/0.32)^2` 是为 V2-M2/M3 原生世界的连续、
亚单位位移标定的（`_ACTIONS` 幅度 0.7，且轨迹平滑）。本集成世界用
离散网格、每步整 1 格位移。1.0 的位移距离直接产生代价约 9.8，
高于"判为丢失"的代价（约 7–9），导致算法系统性地更倾向于宣布正常
移动的实体"丢失"而不是正确关联。**已缓解**：把探测坐标按 0.32 缩放后
再喂给 `OnlineEntityGraph`（不修改该已验证组件本身），运动尺度恢复到
其标定区间。

**2. Track 从不过期，长遮挡下失控漂移。** 未匹配的 track 会持续用
自己的 theta/自主速度外推位置，`OnlineEntityGraph` 没有内置的
track 过期或回收机制——这在 M2 原生世界里没问题（遮挡短、探索是
固定循环的 4 动作序列，噪声小）。但在 M4 风格的长遮挡加随机动作下，
仅凭几个带噪样本拟合出的 track 会外推出网格之外、永不被重新关联，
永久占用有限的 track 名额（16 个很快耗尽）。**部分缓解**：在集成层
（不改 `entity_graph.py`）加了越界+长期低置信 track 回收，`n_tracks`
从稳定卡在上限降到个位数，但自我识别仍未恢复。

**3. 孤立探测器在密集网格里频繁失效。** 用于喂给实体图的"3×3 邻域内
恰好一个占据格"孤立性判据，在 11×11 窗口、5 个物理实体（2 静态+3
移动）共存的场景里极不稳定——单帧孤立探测数在 100 帧样本里从 0 到 5
剧烈波动（0:1 次、1:21 次、2:42 次、3:53 次、4:47 次、5:36 次）。
这与 M2 原生世界（物体在连续空间里天然分离，探测数恒定为 3）形成
鲜明对比。频繁的孤立性丢失直接打断身份连续性，RLS 控制证据
（需要连续多步同一 track 才能累积过阈值）从未建立起来。

## 判断：不再继续打补丁

前两处已经用合理的集成层手段缓解（坐标缩放、越界回收），但第三处
（孤立探测器的根本脆弱性）需要一个真正的连通分量/blob 分割前端才能
解决——这是新的工程工作，不是参数调整。按项目一贯的停止纪律（M1
扩展机制阶段的先例：达到某个失败模式后停止继续调参，先诊断根因，
再决定是否需要新的预注册），这里选择停止而不是继续堆迭代。

## 这次尝试证明了什么

1. **系统级验证是可执行的**：三次修订前的判断"现有验证手段无法把
   系统级环验证成闭合"不再成立——写了协议、写了度量、跑出了明确的
   通过/失败判定。环从"无法验证"变成了"验证了，而且失败，原因
   明确"。
2. **两个独立验证过的组件不能免验证地拼在一起**：M2 和 M4 各自的
   验证只覆盖了各自原生世界的假设（运动尺度、遮挡时长、探测密度）。
   合并使用会打破这些隐含假设，而这些假设此前从未被写下来过——
   本次集成把它们变成了显式的、可检验的事实。
3. **下一步不是重连 M2，是先修前端**：在对象层面做真正的可靠探测
   （连通分量分割或类似机制）之后，再重跑这个协议，才是诚实的
   下一步；直接跳去更复杂的原对象永久性 M2 会把同样的前端问题
   带过去、藏得更深。
